# PimpMyBakkie

A photo-first, realism-focused bakkie configurator.

## Product rule

The user's actual photo is the visual source of truth. Do not substitute a generic cartoon or game-style vehicle. The app captures/imports a real photo, identifies the likely vehicle, asks the owner to confirm the make/model/trim, and uses an image-editing service to create realistic accessory concepts while preserving the same viewpoint.

## Current implementation

- Unity 6 / C# client with photo import on Windows and camera capture on supported devices.
- AI identification workflow with an owner confirmation/edit form.
- Selectable accessory concepts: bullbar, all-terrain tyres, black alloys, suspension lift, snorkel, canopy, spotlights, window tint and paint colours.
- Original/edited image comparison.
- Configurable photo-service URL and app token with a service health test.
- ASP.NET Core backend in `PimpMyBakkie.Api` that keeps the provider API key off the Unity client.
- Image edits are explicitly labelled as concepts, not proof of mechanical compatibility or legal fitment.

## Start the local photo service

See [`PimpMyBakkie.Api/README.md`](PimpMyBakkie.Api/README.md). On Windows run `PimpMyBakkie.Api/run-api.ps1`, enter an OpenAI API key, and keep the service window open. API usage can incur separate charges.

The local service defaults to `http://127.0.0.1:5078`. In Unity, open **API Settings**, check the URL, save, and use **Test**. The access token generated by the script must be entered in API Settings.

## Important limitations

- Vehicle recognition is a best-effort AI suggestion; owners must verify the result.
- Image edits may change details despite strict instructions. Always compare against the original.
- An edited photo is not a validated engineering model. A production library of exact vehicle variants and verified accessory compatibility remains necessary for accurate 360-degree fitting, measurements, price quotes and performance estimates.
- The local backend does not include a hosted production deployment. Do not expose it publicly without HTTPS, authentication, rate limiting and spending controls.
